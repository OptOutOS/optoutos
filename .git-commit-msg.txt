Web GUI: household management (issue #13) + switch to Hono (from Fastify)

Household management (issue #13, TDD):
- Moved addPerson/editPerson/listPeople/linkPeople from apps/cli into
  packages/core/src/people/person-commands.ts so both the CLI and web GUI
  share one implementation instead of duplicating household-mutation
  logic. apps/cli now imports these (and PersonFieldsInput) from
  @optoutos/core; the old local copy and its test were deleted, the test
  itself moved verbatim into core (7 tests, unchanged assertions).
- New web routes: GET/POST /api/people, GET/PATCH /api/people/:id,
  backed by LocalEncryptedFileStore (path via OPTOUTOS_WEB_STORE_PATH,
  passphrase from the unlock session built in the previous slice). Every
  route requires an unlocked session first (423 Locked otherwise) -- same
  privacy-minimization discipline as the rest of the project: never touch
  the encrypted store without an explicit, session-scoped unlock.
- Minimal vanilla-JS frontend (public/index.html, app.js, app.css) --
  unlock screen + household table + add-person form. No frontend
  framework/build step, matching this project's minimal-dependency-
  footprint philosophy for a PII tool.
- Live-verified beyond unit tests: real HTTP round-trip against the
  compiled server with a real encrypted file on disk (create -> list ->
  patch), not just Fastify/Hono inject()/request() mocks.

Framework switch: Fastify -> Hono (user asked "Did we do a comparison of
fastfy vs others?" -- the honest answer was no, Fastify had been picked
without a real comparison). Comparison done retroactively (schema
validation fit with this codebase's existing zod-first convention,
TS-native route typing, runtime portability) and acted on same-day:
- Replaced fastify + @fastify/static with hono + @hono/node-server +
  @hono/node-server/serve-static.
- All 18 existing tests (unlock/session, static serving, household CRUD)
  rewritten against Hono's app.request() test API and re-verified GREEN
  with identical behavior -- a real regression-free swap, not assumed.
- Dependency security discipline applied to the swap: hono <4.12.25 has a
  Windows-specific backslash path-traversal CVE (directly relevant --
  this project runs on Windows); @hono/node-server <2.0.5/<1.19.15 has a
  repeated-slash middleware bypass and an auth-bypass-via-inconsistent-
  URL-decoding bug. Verified current npm versions (hono@4.13.7,
  @hono/node-server@2.1.1) are well past all three fixes before pinning;
  npm audit confirmed 0 vulnerabilities. Same standard already applied to
  @fastify/static earlier the same session (it also had real
  path-traversal CVEs, fixed by pinning ^10.1.3).

docs/DESIGN.md decision 12 and docs/ROADMAP.md item 9 updated with the
full comparison table and real scope shipped.

Full clean-install verification: 227 tests total (166 core + 43 CLI + 18
web -- CLI's -7/core's +7 is the person-commands.test.ts move, confirmed
